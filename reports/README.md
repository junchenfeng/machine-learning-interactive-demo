# reports/ · 研究笔记（Research Note）

学生课后与 AI 对话完成的探究作业。**成品报告由 AI 产出用于外化，附录里的对话原文用来评价学生的思考深度。**

## 三份笔记

| 文件 | 目标变量 Y | 样本 | 难度 | 归属 |
|---|---|---|---|---|
| `research-note-1.md` | 物种（阿德利 vs 帽带） | 143 只，100% 训练 | 基础 | **L2 必做**（课内最后 8′ 开头，课后做完） |
| `research-note-2.md` | 性别（母 vs 公） | 216 只，100% 训练 | 进阶（多一题挑战 Q4，**最多 4 轮收束**） | **选做** |
| `research-note-3.md` | 性别（母 vs 公） | 216 只练 / **117 只封存** | 最高（三站网格搜索） | **L3 课内做第一站，L4 课内做第二三站，课后收尾** |

笔记 1、2 模板相同、四组参数相同（`max_depth` ∈ {1,2} × `min_samples_leaf` ∈ {10,60}），**只有要预测的类别（Y）换了、样本也换了**。

### 🔴 笔记 1、2 的四条设计约束（别改回去）

1. **不押注**：没有"开牌前先猜哪组最准"这一环。学生一上来就看已经算好的数据。
2. **方法只有一句**：换不同参数组合各训练一棵决策树 → 用**准确率（accuracy）**当评价指标 → 挑分得最准的那一棵；
   **准确率打平时取更简单的模型（奥卡姆剃刀 Occam's razor）**。笔记 1 就靠这条定最佳模型：95.8% 是两组并列
   （`max_depth`=1 与 2，`min_samples_leaf`=10），取更浅的 **`max_depth`=1**。
3. **数据全部预填**：四组准确率、最佳模型的混淆矩阵与分类规则**都写在笔记第三章里**。
   原因有二：省课堂时间；且学生与 AI 是**纯对话模式**，Agent 写不了文件，预填后它只需"贴出来"，不需要现场训练或改表。
4. **术语用规范名，不用俗称**（也**不许**写成"旋钮"）：`max_depth`（树最多问几层）、`min_samples_leaf`（叶节点最少样本数）、
   叶节点、特征、类别、基线（baseline）、混淆矩阵、训练集 / 测试集、准确率（accuracy）、阈值、奥卡姆剃刀（Occam's razor）。
   ⚠️ 网站 Tab 05 面板上把这两个参数简写作 `depth` / `min-leaf`——**简称只允许出现在谈网站按钮时**，
   笔记里每次提到都必须给出规范名，并标出两者是同一组参数。

笔记 3 是另一个形态：**训练/验证切分 + 三站网格搜索**（决策树 / 打分模型 / 随机森林）。

### 🔴 笔记 3 的两条特殊机制

1. **封存机制**：学生对 AI 说「**解封验证集**」之前，Agent **不许**出现验证集那一列。
   L3 的全部力气都在"孩子先按训练集挑错、再被自己推翻"上，剧透一次全课作废。
2. **随机森林必须用预计算数字**：换随机种子验证集会落在 **84.6%–88.9%**。
   25 个孩子各跑一次 = 25 张不同的表，"谁赢了"没法比较。
   笔记的 Agent 指令里写死了「以 JSON 为准」。

## 使用方式

学生对自己的 AI 说一句口令，剩下的由 AI 引导完成：

- 笔记 1 → 「引导我完成企鹅研究笔记 1」
- 笔记 2 → 「引导我完成企鹅研究笔记 2」
- 笔记 3 → 「引导我完成企鹅研究笔记 3」，第一站内另有口令「**解封验证集**」

口令触发的流程写在每份笔记开头的「给 Agent 的指令（学生不用读这一节）」里：
取数 → 先导览 → **直接贴出已经预填在第三章的研究数据** → 不代答 → 每轮记附录 → 收尾出外化报告 → 等老师说「**发布笔记**」。

笔记 2 的挑战题 Q4 **最多讨论 4 轮就收束**：只看学生的直觉方向，不要求他给出最好的方案。

## 数字从哪来

**数字全部预计算，禁止 AI 自行估算或改写。** 两个唯一事实源：

```
reports/data/research-note-data.json    # 笔记 1、2（100% 训练）
reports/data/research-note-3-data.json  # 笔记 3（216 练 / 117 验证，random_state=42）
```

重新生成：

```bash
python3 scripts/generate_research_note_data.py     # 笔记 1、2
python3 scripts/generate_research_note_3_data.py   # 笔记 3
```

（都需 scikit-learn）

建模配置与网站 Tab 05「训练决策树」同源：`DecisionTreeClassifier(criterion="gini", random_state=42)`，
笔记 1、2 是 100% 训练（不划分训练集与测试集，`year ∈ {2007, 2008}`）；
笔记 3 是 **2007+2008 训练 / 2009 验证**。

⚠️ **两份笔记的样本不同，这是故意的**：笔记 2 若也只取阿德利+帽带（n=138），
四组准确率会挤成 84.8 / 84.8 / 85.5 / 84.8，分不出高低。
取三种企鹅全量（n=216）才有真正的档次差：72.7 / 88.0 / 72.7 / 80.1。

## 改数字时必须同步的三处

1. `reports/data/research-note-*.json`（重新生成）
2. 笔记里**第三章的预填表格 + 最佳模型混淆矩阵 + 分类规则**，以及「给 Agent 的指令」的**数据包**兜底块
3. `unit3-lesson{2,3,4}-plan-*.md` 的附录一数字

## 笔记 3 的三站网格（教师推荐网格，写在笔记里）

| 站 | 模型 | 网格（参数取值） |
|---|---|---|
| 一 | 决策树 | `max_depth` {1,2,3,5,不限} × `min_samples_leaf` {1,20} = **10 组**（另有派生列"**最终叶节点数**"） |
| 二 | 打分模型（逻辑回归） | 管束力度 C ∈ {0.01, 0.1, 1, 10, 100} = 5 组（**倒 U**：79.5 / 85.5 / **87.2** / 87.2 / 85.5） |
| 三 | 随机森林 | 树的数量 {10,100} × 每棵树的 `max_depth` {1,3,不限} = 6 组（`min_samples_leaf` 固定 1） |

三站最佳在验证集上：**决策树 `max_depth`=2 → 88.0%（103 只）** / 打分 C=1 → 87.2%（102）/ 随机森林 100 棵、`max_depth`=3 → 87.2%（102）。
→ **换模型差 1 只，调参数差 6 只**（不限 → 82.9%，97 只）。这是 L4 的落点。

## 发布笔记（教师对 AI 说「发布笔记」时执行）

口令就是一句 **「发布笔记」**（说「发布笔记 1 / 2 / 3」或直接给编号则只发那一份；没给编号就问清是哪一份，不要默认全发）。

网页端页面：`/notes.html`（笔记本 UI，三个页签 = 笔记 1 / 2 / 3）。
内容源：`src/data/research-notes.json` —— 数组元素形如
`{ id, title, subtitle, level, source, published, markdown }`。
**未发布（`published: false`）或 `markdown` 为空的笔记，页面只显示空白占位，不显示任何正文**。

发布某份笔记（编号 N）时，AI **必须同时改两处、缺一不可**：

1. **写 md 文件** —— 把该笔记的完整 Markdown 源写成 `reports/research-note-{N}.md`（**含**开头「给 Agent 的指令（学生不用读这一节）」一节 + 第一～四章 + 附录）。
2. **同时修改对应的笔记 html** —— 把同一份正文**剔除「给 Agent 的指令（学生不用读这一节）」小节**后（那是给学生 AI 的操作手册，学生看到会提前知道追问策略与 Q4 收束规则），写入 `src/data/research-notes.json` 中 `id === N` 的条目：
   - `markdown` = 处理后的正文全文（JSON 转义）
   - `published` = `true`
   - `title` / `subtitle` / `level` / `source` 保持不变
3. 只改目标条目，**其余条目一律保持未发布**。
4. 验证：`pnpm ts-check` + `pnpm build` 通过；启动 dev server 打开 `/notes.html`，确认该页签渲染出标题层级、表格、列表，其他页签仍是空白占位。

> 为什么分开两步：学生与 AI 是**纯对话模式**（Agent 写不了文件），所以课堂里 Agent 只把报告贴在对话里；
> 真正落盘（md + html）由老师在能写文件的环境里用「发布笔记」一次完成。

补充：

- 学生对话原文另存 `note-logs/note-{N}.json`（结构与用途见 `note-logs/README.md`），网页端不展示，仅供外部批分引擎通过 `GET /note-log/{N}` 拉取。
- 笔记 3 的「解封验证集」机制只在学生与 AI 的对话里生效，与网页发布无关。
